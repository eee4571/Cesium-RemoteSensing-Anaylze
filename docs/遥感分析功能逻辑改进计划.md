# 遥感分析功能逻辑改进计划

检查日期：2026-05-23

本文按本地 skills 的工作方式重新整理：先固定当前代码事实，再给出可执行的分阶段计划。后续真正改代码时，优先按“测试先行、边界清楚、小步验证”的顺序推进。

## 1. 当前代码事实

### 1.1 后端分析链路

核心文件：`backend/app/main.py`

当前后端把上传、预览、GEE、指数计算、变化检测和结果文件服务都放在同一个文件中。

主要入口：

- `POST /upload/tiff`：上传 GeoTIFF，返回宽高、波段数、CRS、范围、分辨率、band descriptions 等元数据。
- `GET /images/{image_id}/preview.png`：生成主影像预览 PNG，预览最大边长当前由 `_preview_png(..., max_size=1200)` 控制。
- `GET /images/{image_id}/sample`：按 WGS84 经纬度采样栅格像元。
- `POST /upload/shapefile`：上传 zipped Shapefile，返回 WGS84 范围和 GeoJSON。
- `POST /gee/fetch`：从 GEE 下载 GeoTIFF，默认波段为 `B2,B3,B4,B8,B11,B12`。
- `POST /analysis/index`：计算 NDVI/NDWI/NDBI 等归一化差值指数。
- `POST /analysis/change`：计算双时相指数差值，并按阈值分为增加、减少、稳定。
- `GET /analysis/{analysis_id}/preview.png`、`result.tif`、`stats.json`：读取分析输出。

当前关键函数：

- `_read_analysis_bands(...)`：读取 A/B 波段，并可按 `bounds_wgs84` 裁剪。
- `_read_aligned_index(...)`：把 after 影像重采样到 before 影像网格。
- `_normalized_difference(a, b)`：使用 `(A - B) / (A + B)` 计算指数。
- `_basic_stats(values)`：统计有效像元、最小值、最大值、均值、标准差。
- `_write_analysis_output(...)`：写出 `result.tif`、`preview.png`、`stats.json`。

### 1.2 前端分析链路

核心文件：`frontend/src/main.tsx`、`frontend/src/CesiumWorkspace.tsx`

当前前端已有：

- 主影像槽位 `raster`。
- 对比影像槽位 `comparisonRaster`。
- GEE 默认下载波段 `B2,B3,B4,B8,B11,B12`。
- 指数波段预设：
  - NDVI：`B8 / B4`
  - NDWI：`B3 / B8`
  - NDBI：`B11 / B8`
- `resolveIndexPreset(...)`：根据 band descriptions 自动匹配波段编号。
- `runIndexAnalysis()`：提交单期指数分析。
- `runChangeDetection()`：提交双时相变化检测。
- `analysisResults`：保存本次浏览器会话中的结果。
- `CesiumWorkspace`：用 `SingleTileImageryProvider` 叠加分析结果预览图。
- 结果弹窗：支持显示开关、透明度、缩放、下载 GeoTIFF 和查看 JSON。

### 1.3 当前测试

后端：

- 尚未覆盖指数公式、裁剪、阈值、变化检测、面积单位和无重叠场景。

## 2. 主要风险判断

### 2.1 必须优先修的风险

1. 面积统计单位可能误导
   - 当前面积用 `abs(transform.a * transform.e) * pixels`。
   - 投影坐标系下通常可以解释为 CRS 单位平方。
   - 经纬度 CRS 下则是平方度，不能直接当平方米。

2. 变化检测缺少有效重叠质量指标
   - after 影像会被重采样到 before 网格。
   - 如果两期影像范围基本不重叠，仍可能输出结果文件。
   - 结果缺少 `overlapRatio`，用户难以判断结果是否可信。

3. 阈值输入不完整校验
   - 指数阈值未校验 `threshold_min <= threshold_max`。
   - 变化阈值只校验大于 0。
   - 对 NDVI/NDWI/NDBI 这类归一化指数，没有给出 `[-1, 1]` 范围提示。

4. 后端核心分析测试不足
   - 当前没有 synthetic raster 测试守住核心数学逻辑。
   - 后续重构或新增算法时，风险会集中爆发。

### 2.2 第二优先级风险

1. 波段语义不够明确
   - 前端能自动匹配 GEE 下载的 band descriptions。
   - 本地上传数据如果没有清楚的波段描述，用户容易算出形式正确但遥感含义错误的结果。

2. 对比影像无法在地图上叠加查看
   - 变化检测前，用户不能直接在 Cesium 中对比 before/after 覆盖和配准。

3. 结果上下文不足
   - 结果弹窗没有完整展示输入影像、使用波段、阈值、面积单位、有效比例等解释信息。

4. zip 解压缺少保护
   - Shapefile 上传和 GEE zip 下载都使用直接解压。
   - 需要补 zip slip 路径检查、文件数量和大小限制。

### 2.3 暂不优先处理的风险

1. 任务队列
   - 同步分析对大数据不理想，但当前课程作业原型可以先通过像元上限和预览尺寸控制降低风险。

2. 数据库和项目管理
   - 当前结果只保存在本地文件和前端会话状态中。
   - 短期不引入数据库，避免把课程原型改成过重系统。

3. 完整生产级瓦片服务
   - 当前用 single tile 叠加分析结果。
   - 短期只控制预览尺寸，不上 COG tile server。

## 3. 推荐总体方案

采用“先可信，再好用，再拆分”的路线。

### 方案 A：先做可信度修复（推荐）

先补后端 synthetic raster 测试，再修阈值、面积单位、有效像元比例和重叠比例。

优点：

- 最直接提高分析结果可信度。
- 改动范围较小。
- 后续 UI 和模块拆分都有测试保护。

代价：

- 短期界面变化不大。

### 方案 B：先做界面体验

先加对比影像叠加、结果上下文和波段选择说明。

优点：

- 演示效果提升明显。
- 用户更容易理解工作流。

代价：

- 如果后端统计和边界逻辑没先稳住，界面会放大不可靠结果。

### 方案 C：先大拆分

先把 `backend/app/main.py` 和 `frontend/src/main.tsx` 拆成多个模块。

优点：

- 长期维护更舒服。

代价：

- 没有测试保护时，大拆分容易引入回归。
- 对当前目标来说风险偏高。

结论：推荐按方案 A 开始。先把分析计算和统计语义守住，然后再做前端体验和模块拆分。

## 4. 分阶段实施路线

### 阶段一：分析可信度修复

优先级：最高

目标：让 `stats.json` 和分析输出不会在常见边界条件下误导用户。

涉及文件：

- 修改：`backend/app/main.py`
- 修改：`backend/test_main.py`
- 可能修改：`docs/网页使用说明.md`

任务：

1. 增加后端 synthetic raster 测试
   - 创建内存或临时 GeoTIFF。
   - 测试 `_normalized_difference`：
     - 正常值。
     - 分母为 0。
     - NaN/nodata。
   - 测试指数阈值统计：
     - `thresholdPixels`。
     - `thresholdArea`。
     - 新增的 `totalPixels`、`validPixels`、`nodataPixels`、`validRatio`。
   - 测试变化检测分类：
     - increase。
     - decrease。
     - stable。
     - invalid/nodata。

2. 增加统计辅助函数
   - 建议新增 `_pixel_quality_stats(values)`：
     - `totalPixels`
     - `validPixels`
     - `nodataPixels`
     - `validRatio`
   - `_basic_stats` 可合并这些质量字段，或保持基础统计并由调用方合并。

3. 增加面积单位辅助函数
   - 建议新增 `_pixel_area_info(meta)`：
     - 投影 CRS：返回像元面积和 `areaUnit`。
     - 经纬度 CRS：先返回清晰单位，例如 `square_degrees`，并在文档中说明不等于平方米。
   - 更严谨的平方米统计可作为阶段二或三的独立任务，避免第一阶段过度复杂。

4. 增加阈值校验
   - `analysis_index`：
     - 如果上下限同时存在，要求 `threshold_min <= threshold_max`。
     - 如果阈值超出 `[-1, 1]`，允许继续或直接拒绝二选一。建议第一版直接拒绝，错误文案说明归一化指数通常在 `[-1, 1]`。
   - `analysis_change`：
     - 保留 `threshold > 0`。
     - 增加 `threshold <= 2`，因为两个归一化指数差值理论范围约为 `[-2, 2]`。

5. 增加重叠质量统计
   - 变化检测中计算 `diff` 后：
     - `overlapPixels = finite(diff)` 数量。
     - `overlapRatio = overlapPixels / totalPixels`。
   - 如果 `overlapPixels == 0`，返回 HTTP 400。
   - 如果 `overlapRatio < 0.05`，建议返回 HTTP 400，并提示两期影像重叠过少。

6. 文档同步
   - 在 `docs/网页使用说明.md` 中补充：
     - 面积单位说明。
     - 有效比例说明。
     - 变化检测需要两期影像覆盖同一区域。

阶段一验收命令：

```powershell
cd backend
python -m unittest -v
python -m py_compile app\main.py
```

通过标准：

- 后端测试覆盖核心分析数学和边界场景。
- 阈值错误、无有效像元、低重叠比例不再生成误导性结果。
- `stats.json` 能解释有效像元比例和面积单位。

   - 对 `B2/B3/B4/B8/B11/B12` 分别标识 Blue、Green、Red、NIR、SWIR1、SWIR2。
